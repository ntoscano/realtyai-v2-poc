## Codebase Patterns
- Port assignments: 54321=realty-ai, 54322=tictactoe, 54323=shift-marketplace, 54324=midi-matching
- App ports: 3003=shift-api, 3004=midi-api
- Always add NestJS apps to root .prettierignore (root uses @trivago/prettier-plugin-sort-imports which fails on TS decorators)
- NestJS apps need a local .prettierrc.js (without the sort-imports plugin) so eslint's prettier/recommended can parse decorators
- Symptom-to-specialty mapping is in src/shared/symptom-specialty-map.ts — reuse in both QuestionnaireService and ClinicianService
- TypeORM DeepPartial<T> does not accept null — use undefined for optional nullable fields in repo.create()
- Include tsconfig.build.json from the start for NestJS apps (nest start --watch requires it)
- shift-api reference files are on ralph/shift-marketplace branch (not main), use `git show ralph/shift-marketplace:path` to view them
- .env.local is NOT committed via .gitignore — need to create manually or in scaffolding step
- Export interfaces used as return types from services — TS 5.9 requires named types in public methods to be exported (TS4053)
- Use innerJoinAndSelect (not leftJoinAndSelect) when using pessimistic_write lock — PostgreSQL FOR UPDATE cannot be applied to nullable side of outer join
- For pessimistic locking: DataSource.createQueryRunner() → connect → startTransaction → setLock('pessimistic_write') → commit/rollback → release in finally
- Cancellation must null out slotId AND set slot relation to null — TypeORM's .save() uses relation objects to infer FK values, so nulling only the FK field is insufficient
- Use leftJoinAndSelect for slot in list queries since cancelled appointments have slotId=null
