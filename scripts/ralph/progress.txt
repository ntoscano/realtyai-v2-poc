## Codebase Patterns
- Port convention: 54321 = realty-ai, 54322 = tictactoe, 54323 = shift-marketplace
- NestJS apps use `dotenv.config({ path: path.join(__dirname, '../.env.local') })` at top of main.ts
- TypeORM config uses `getConfig()` from postgres.ts for connection params
- SnakeNamingStrategy for all TypeORM entities (camelCase TS -> snake_case DB)
- `synchronize: true` for POC apps (no migrations needed)
- Global ValidationPipe with `whitelist: true` and `forbidNonWhitelisted: true`
- Entity files live in `entities/` subdirectory under each module
- `@Index` for composite indexes goes at class level above `@Entity`
- Cross-module entity imports use relative paths (e.g., `../../shift/entities/shift.entity`)
- New NestJS apps MUST be added to root `.prettierignore` (root uses @trivago/prettier-plugin-sort-imports which fails on TS decorators)
- New NestJS apps MUST have `.eslintrc.js` copied from tictactoe-api (with `root: true`, `@typescript-eslint/parser`, decorator support)
- Pre-commit hooks: husky + lint-staged runs eslint + prettier from repo root on staged files
- Controllers use `@Controller('api')` prefix; DTO files go in `dto/` subdirectory under each module
- Use createQueryBuilder with `.andWhere()` for optional filter patterns in findAll methods
- Left join related entities (booking + professional) in shift queries to include nested data
- For pessimistic locking: inject `DataSource`, use `createQueryRunner()`, `setLock('pessimistic_write')`, commit/rollback/release pattern
- Booking controller uses `@Controller('api/shifts')` — sub-resources use the parent resource path prefix
- NestJS apps MUST have `tsconfig.build.json` (extends tsconfig.json, excludes test/spec) — `nest start --watch` requires it
- PostgreSQL `FOR UPDATE` cannot be applied to nullable side of outer join — use `innerJoinAndSelect` instead of `leftJoinAndSelect` when locking rows with related entities
- Booking endpoint should return HTTP 200 (not 201) — use `@HttpCode(200)` on the controller method
- New Next.js apps MUST also be added to root `.prettierignore` (same as NestJS apps)
- Frontend port convention: 2025 = tictactoe, 2026 = shift-ui
- Frontend API client pattern: `apiFetch<T>()` wrapper with typed error handling, API_URL from `NEXT_PUBLIC_API_URL` env var
- shadcn/ui components go in `src/components/ui/` — copy badge, button, card from tictactoe as baseline
- No select.tsx in tictactoe — use native HTML select styled with `border-input bg-background px-3 py-2 text-sm rounded-md` to match theme
- Backend GET /api/shifts does not support facilityId filter — filter client-side after fetching with status=all
